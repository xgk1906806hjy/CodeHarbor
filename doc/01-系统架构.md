# 系统架构

## 总体结构
首版采用前后端分离 Web 架构：浏览器负责页面展示和交互，后端提供认证、内容、互动、搜索和管理 API，数据库保存业务数据，文件存储保存头像、封面和内容图片。

## 分层
- 表现层：路由、页面、组件、表单和响应式布局。
- 应用层：用例编排、权限判断、参数校验和事务边界。
- 领域层：用户、博客、工具、需求、评论和审核规则。
- 基础设施层：数据库、缓存、对象存储、日志和外部链接检查。

## 主要模块
- auth：注册、登录、会话和权限。
- user：个人资料、主页和关注关系。
- blog：博客草稿、发布、阅读和评论。
- tool：工具条目、筛选、收藏和评价。
- requirement：需求发布、响应和状态流转。
- interaction：点赞、收藏、关注、评论和通知。
- search：全局搜索、筛选和排序。
- moderation：审核、举报、下架和操作日志。

## 请求链路
页面请求 -> API 路由 -> 身份认证 -> 参数校验 -> 应用服务 -> 领域规则 -> 数据访问 -> 统一响应。

## 原则
- API 不直接暴露数据库模型，使用响应 DTO。
- 公开内容只返回已发布且未删除的数据。
- 管理员能力通过独立权限守卫保护。
- 业务状态变化必须经过领域规则。
